# План переноса «Права Силы» в Godot

Цель: превратить прототип в полноценный редактируемый проект на **Godot 3.6 LTS**
(он же лучше всего ложится на Anbernic H700 через PortMaster/FRT).

Базовое разрешение — 320×240, пиксель-перфект, целые масштабы.

---

## Кто что делает

### Вы

1. Утверждаете стиль и палитру (по первым пробам от ГПТ).
2. Прогоняете промты из `art-prompts.md` в ГПТ и приносите готовые PNG.
3. Принимаете ассеты по чек-листу (размер, сетка, прозрачный фон, без сглаживания).
4. Тестируете сборки на H700 и говорите, что не так по ощущениям.

### ГПТ

Рисует по промтам: тайлсеты, персонажей с анимациями, зверей, предметы, интерфейс, эффекты.
Формат отдаёт строго по требованиям ниже — иначе кадры не соберутся в анимацию.

### Я

1. Создаю проект Godot: структуру папок, автолоады, настройки пиксель-перфекта и ввода.
2. Нарезаю ассеты, собираю TileSet'ы и сцены локаций.
3. Переношу логику из JS в GDScript по модулям и проверяю по шагам.
4. Собираю билд под PortMaster и веду репозиторий.

## Требования к ассетам (важно)

| Что | Размер | Формат |
|---|---|---|
| Тайлы | 16×16 | PNG-атлас, сетка без отступов, кратно 16 |
| Персонажи и NPC | 16×24 (кадр) | Спрайт-лист: строки — направления, столбцы — кадры |
| Звери мелкие (заяц) | 16×16 | Спрайт-лист |
| Звери крупные (шипогрыз, прыгун, метатель) | 24×24 | Спрайт-лист |
| Большой прыгун (босс) | 48×48 | Спрайт-лист |
| Предметы и иконки | 16×16 | Отдельные PNG или атлас 8×8 иконок |
| Эффекты | 32×32 | Спрайт-лист, 4–6 кадров |

Общие правила: прозрачный фон, **без сглаживания и полупрозрачных краёв**, единая палитра,
не больше 32 цветов на ассет, вид сверху три четверти, источник света — сверху.

Анимации персонажа: `idle` 2 кадра, `walk` 4, `attack` 3, `dash` 2, `hurt` 1, `die` 3 —
для четырёх направлений (вниз, вверх, вбок; вбок отзеркаливаем).

Именование файлов: `hero_walk.png`, `tiles_forest.png`, `beast_spiker.png`, `ui_bars.png`.

## Структура проекта Godot

```
project.godot
autoload/      GameState.gd  Quests.gd  Story.gd  Audio.gd
scenes/
  world/       Forest.tscn  City.tscn  Slums.tscn  Road.tscn ...
  actors/      Player.tscn  Beast.tscn  NPC.tscn  Hunter.tscn
  ui/          HUD.tscn  Dialog.tscn  Inventory.tscn  Board.tscn
  fx/          Blast.tscn  Hit.tscn  Dust.tscn
scripts/       player.gd  beast.gd  npc.gd  quests.gd ...
assets/
  tiles/  sprites/  ui/  audio/
data/          quests.json  dialogs.json  spawns.json
```

Логика — в автолоадах, контент — в данных. Тогда сюжет правится без переписывания кода.

## Этапы

| Этап | Что делается | Результат |
|---|---|---|
| 0. Решения | Версия Godot, палитра, размеры, стиль | Утверждённый стайлгайд |
| 1. Каркас | Проект, пиксель-перфект, ввод, автолоады, пустая сцена | Герой ходит по тестовой карте |

| 3. Игрок и бой | Движение, рывок, нож, урон, смерть, сохранения | Глава 1 проходится |
| 4. Диалоги и квесты | Данные из JSON, журнал, доска заказов | Глава 2 проходится |
| 5. Город и интерьеры | Тайлы города, NPC, переходы между сценами | Все локации собраны |
| 6. Способности | Выброс, щит, притягивание + головоломки | Глава 3 |
| 7. Сборка | Экспорт Linux ARM64, упаковка под PortMaster | Играется на H700 |

## Что мне нужно, чтобы начать собирать сцены

1. **Палитра** (16–32 цвета) одним PNG или списком HEX.
2. **Герой**: `hero_idle`, `hero_walk`, `hero_attack`, `hero_dash`, `hero_hurt` по требованиям выше.
3. **Тайлсет леса**: трава (3 варианта), тропа, деревья, кусты, валуны, брёвна, вода, камни.
4. **Тайлсет города и трущоб**: мостовая, грязь, стены и крыши домов (3 цвета), двери, заборы, прилавки, канава.
5. **Интерьеры**: пол, стены, кровать, стол, печь, полка, сундук, стойка, ковёр, коврик-выход.
6. **Звери**: шипогрыз, костяной прыгун, метатель, кабан, заяц + большой прыгун.
7. **Люди**: 8–10 вариантов горожан, стражник, охотник, клерк, трактирщик, извозчик, сборщик.
8. **UI**: рамка диалога, рамка меню, полоски (здоровье, выносливость, энергия, токсины), иконки предметов, стрелка-указатель.
9. **Эффекты**: удар ножом, удар силы (кольцо), пыль от рывка, искры кристалла, кровь.

Как только будут пункты 1–3, я начинаю собирать каркас и первую играбельную сцену,
остальное подключаем по мере готовности.

## Чем помогает текущий прототип

JS-версия остаётся эталоном поведения: тайминги атак, дистанции, урон, тексты диалогов и сценарий.
При переносе я сверяюсь с ней, а не изобретаю заново. Файлы `docs/design.md` и `docs/chapters-3-6.md` —
источник правды по сюжету и системам.
