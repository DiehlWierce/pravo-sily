# Архитектура прототипа

Чистый JavaScript без сборки: обычные `<script>` в `index.html`, у каждого файла одна ответственность.
Модули общаются через глобальные объекты с понятными именами, а сюжет подключается к движку через шину событий.
Так устроен и Godot: глобальные объекты — это автозагрузки (autoload), классы сущностей — сцены со скриптами, события — сигналы.

## Слои и порядок загрузки

Порядок в `index.html` важен: каждый слой опирается только на предыдущие.

| Слой | Папка | Что внутри | В Godot |
|---|---|---|---|
| Движок | `js/engine/` | математика, события, ввод, звук, частицы и свечение силы, холсты и текст, тайловый мир, физика тел, поиск пути | встроенные узлы + autoload `Events` |
| Графика | `js/art/` | спрайты и тайлы, нарисованные кодом | SpriteFrames, TileSet (из листов художника) |
| Данные | `js/data/` | баланс, вещи, звери, жители и реплики, лавки, заказы, поручения | ресурсы `.tres` / JSON |
| Сцены | `js/scenes/` | ASCII-карты городов, генераторы леса, расстановка спавна | `.tscn` с TileMap |
| Сущности | `js/entities/` | герой, звери, охотник, люди, живность, предметы мира | сцены-персонажи со скриптами |
| Системы | `js/systems/` | вещи, спавн, кражи, лавки, разговоры, заказы, поручения, сохранения | autoload-синглтоны |
| Сюжет | `js/story/` | главы 0, 1, 2 — отдельные модули | скрипты глав, подписанные на сигналы |
| Интерфейс | `js/ui/` | диалог, меню вещей, свиток, HUD, титульный экран | Control-сцены |
| Игра | `js/game.js`, `js/main.js` | сцены и переходы, списки сущностей, камера, цикл | главная сцена |

## Шина событий

Движок не знает про сюжет. Он сообщает, что случилось, а главы решают, что с этим делать.

```js
Events.on('kill', e => …)                   // подписаться
Events.emit('kill', enemy)                  // оповестить всех
Events.allow('can:enter', 'city')           // спросить разрешения: false от любого подписчика — нельзя
Events.handle('npc:talk', npc)              // первый, кто вернул true, забирает событие
```

| Событие | Когда | Кто слушает |
|---|---|---|
| `scene:load (имя)` | сцена загружена и расставлена | главы, заказы, поручения |
| `tick (dt)` | каждый кадр игры | главы |
| `kill (зверь)`, `loot (зверь)` | убит, разделан | главы, заказы |
| `container`, `junk` | обыскан тайник, куча хлама | глава 0 |
| `campfire (костёр, разожжён сейчас)` → handle | подошёл к костру | глава 1 |
| `rest`, `ate` | отдохнул, поел | главы 1, 2 |
| `can:talk`, `can:enter`, `can:rest`, `can:loot` → allow | можно ли | главы |
| `npc:talk` → handle | разговор с жителем | главы (родители, клерк, извозчик) |
| `chase:spotted / caught / lost / talked` | погони | глава 0 |
| `theft:caught` | поймали на краже | — |
| `hunter:provoked / down / looted / cut`, `spiker:reveal` | охотник и шипогрыз | глава 1 |
| `quest:done`, `errand:done`, `shop:bought`, `coins:changed` | награды и покупки | главы |
| `game:loaded`, `game:beforeSave`, `respawn` → handle | загрузка, сохранение, смерть | главы |

## Как добавить…

**Жителя.** Строка в спавне сцены: `['npc', x, y, { who: 'палитра', role: 'ключ' }]`, описание в `data/personas.js`.
Разговор, лавка, скупщик, милостыня и поручения соберутся сами. Особый разговор — подписка на `npc:talk` в главе.

**Лавку.** Ключ в `data/shops.js`, в персонаже — `shop: 'ключ'`.

**Поручение горожанина.** Запись в `data/errands.js`: кто даёт, что принести (`need`), что вручить (`give` / `deliver`),
найти вещь (`find`) или человека (`escort`), награда. Логика — `systems/errands.js`, ничего писать не нужно.

**Заказ гильдии.** Запись в `data/quests.js`: `kill`, `item` или `find`, ранг, награда, особые звери (`spawn`).

**Зверя.** Характеристики — `data/enemies.js`, класс с поведением — `entities/beasts.js`, строка в `ENEMY_TYPES` (`systems/spawn.js`).
Если зверь силы — переопределите `forceGlow()`, чтобы он светился в нужных состояниях.

**Сцену.** Город — ASCII-карта в `scenes/maps/towns.js` + описание в `scenes/chapterN.js` (`map`, `spawns`, двери через `paintTown`).
Лес — генератор `build(P)` с `carvePath` и `overgrow`.

**Главу.** Файл `story/chapterN.js` с объектом `{ id, init(), start(), objective() }`, в конце `Story.register(ChapterN)`,
подключить в `index.html` после предыдущей главы.

**Раздел меню.** Объект в `MENU_SECTIONS` и функция с тем же id в `MenuSections` (`ui/menu.js`), которая возвращает строки
`{ label, value, icon, desc, a, x, left, right, header }`. Разметка, прокрутка, описание и подсказки рисуются сами.

**Настройку.** Запись в `Settings.DEFS` (`systems/settings.js`) — пункт появится в меню и на титульном экране.
Хранится отдельно от сохранения, «Начать заново» её не сбрасывает.

## Правила, которые легко сломать

- **Направление взгляда людей** — только `'l'` или `'r'`. Остальное рисуется как «вправо» (раньше `'d'` ронял отрисовку).
- **Урон** — через `Combat.hit(цель, урон, dx, dy, источник, атакующий)`. Опыт и заказы засчитываются, только если зверя добил герой.
- **Кто на кого нападает** — таблица `Factions` в `data/enemies.js`. `sticky` держит зверя на своей цели.
- **Завалы** — `World.barrier(x, закрыт)`: перекрывают столбец на всю высоту карты и сдвигают того, кто в нём стоял.
- **Сохранение** — только `Game.flags`, `Game.removed` и герой. Всё, что появляется в сцене по сюжету, глава восстанавливает в `scene:load`.
- **Застревание в геометрии** — `Enemy.unstick()` вытаскивает тело из дерева или стены. Боссу нужен ещё и запасной выход
  из тупика (у охотника: обход по `Nav`, вырывание камня из земли, усталость по таймеру), иначе глава становится непроходимой.
- **Ошибка в кадре** не останавливает игру: `main.js` пишет её в консоль и красной полосой на экран.

## Проверка

`python3 -m http.server 8791`, открыть `http://localhost:8791/?smoke`. Автотест (`tests/smoke.js`) прогоняет все сцены
с отрисовкой, цепочки глав 0–2, кражи, поручения, поиск пути, бой охотника, старые сохранения и замеряет скорость кадра.
Тест стирает сохранение.
